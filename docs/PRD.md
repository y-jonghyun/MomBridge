# 지역 마케팅 미션 매칭 플랫폼 (HyperLocal Mission Platform) PRD

> **문서 버전:** v1.0
> **작성일:** 2025년 기준
> **상태:** MVP 개발 착수 준비 완료

---

## 1. 프로젝트 개요

### 배경 및 목적

지역 소상공인은 예산 부족과 마케팅 전문성 부재로 효과적인 홍보 수단을 찾지 못하고 있다. 동시에, 지역 주민 중 일부는 자신의 SNS 채널이나 방문 경험을 활용해 소득을 창출하고자 하는 수요가 존재한다. 본 플랫폼은 이 두 수요를 **하이퍼로컬(Hyper-Local) 미션 매칭** 구조로 연결하며, 운영자가 중간에서 품질을 보증하는 **3자 구조**로 신뢰성을 확보한다.

> **핵심 가치 제안:** "소상공인은 저렴하게 진성 콘텐츠를 얻고, 지역 주민은 일상 활동으로 수익을 창출한다."

### 핵심 목표

| 목표 | 측정 지표 (KPI) |
|------|----------------|
| 소상공인 홍보 비용 절감 | 기존 SNS 광고 대비 CPM 50% 절감 |
| 참여자 활성화 | 월간 활성 참여자(MAU) 500명 (3개월 내) |
| 플랫폼 신뢰성 확보 | 콘텐츠 검수 승인률 80% 이상 유지 |
| 고객사 재계약율 | 3개월 내 고객사 재의뢰율 40% 이상 |
| MVP 출시 | 기획 확정 후 10주 내 베타 런칭 |

## 2. 타겟 사용자

### 주요 사용자 페르소나

---

#### 👤 페르소나 A — 운영자 (Operator)

```
이름: 김운영 (내부 스태프)
역할: 플랫폼 전체 운영 총괄
목표: 미션 품질 유지, 정산 정확성, 고객사 만족도 관리
Pain Point:
  - 수십 건의 인증 콘텐츠를 수작업으로 검수해야 함
  - 정산 오류 발생 시 신뢰도 급락
  - 고객사와 참여자 양측 민원을 동시에 처리해야 함
필요한 것: 통합 대시보드, 빠른 검수 UI, 정산 자동화 도구
```

---

#### 👤 페르소나 B — 참여자 (Participant)

```
이름: 이지원 (28세, 직장인 겸 인스타그래머)
역할: 미션 수행 후 인증 콘텐츠 제출
목표: 일상 활동으로 부수입 창출
Pain Point:
  - 어떤 미션이 나에게 맞는지 탐색이 어려움
  - 보상 지급 시점이 불투명함
  - 반려 사유를 명확히 알지 못해 재제출이 어려움
필요한 것: 직관적 미션 탐색, 명확한 보상 조건, 신속한 피드백
```

---

#### 👤 페르소나 C — 고객사 (Client / 소상공인)

```
이름: 박사장 (45세, 동네 카페 운영)
역할: 홍보 미션 의뢰
목표: 실제 방문객이 만든 진성 콘텐츠로 인지도 상승
Pain Point:
  - SNS 광고는 비싸고 효과가 불명확함
  - 결과물을 확인하기 어려움
  - 마케팅에 할애할 시간이 없음
필요한 것: 간단한 의뢰 등록, 실시간 진행 현황, 명확한 결과 리포트
```

## 3. 핵심 기능 (MVP)

> 우선순위 기준:
> - 🔴 **P0** — MVP 런칭 블로커 (반드시 구현)
> - 🟡 **P1** — MVP 포함 권장 (핵심 UX 완성도)
> - 🟢 **P2** — Post-MVP 고도화

---

### 3-1. 인증 & 계정 관리

| 우선순위 | 유저 스토리 |
|---------|------------|
| 🔴 P0 | **참여자/고객사**는 플랫폼을 이용하기 위해 이메일과 비밀번호로 회원가입을 할 수 있다. |
| 🔴 P0 | **모든 사용자**는 보안 유지를 위해 JWT 기반 로그인/로그아웃을 할 수 있다. |
| 🔴 P0 | **운영자**는 플랫폼 관리를 시작하기 위해 시드(Seed) 계정으로 로그인할 수 있다. |
| 🟡 P1 | **참여자**는 매칭 품질을 높이기 위해 활동 지역과 보유 SNS 채널 정보를 프로필에 등록할 수 있다. |
| 🟢 P2 | **참여자/고객사**는 간편 가입을 위해 카카오/네이버 소셜 로그인을 사용할 수 있다. |

---

### 3-2. 미션 관리 (운영자 주도)

| 우선순위 | 유저 스토리 |
|---------|------------|
| 🔴 P0 | **운영자**는 홍보 미션을 생성하기 위해 카테고리(방문/SNS/리뷰/영상), 지역, 보상금액, 모집인원, 마감일을 설정할 수 있다. |
| 🔴 P0 | **운영자**는 미션 진행 상황을 통제하기 위해 미션 상태를 `draft → open → in_progress → reviewing → closed` 순으로 전환할 수 있다. |
| 🔴 P0 | **운영자**는 적합한 참여자를 선별하기 위해 지원자 목록에서 개별 승인 또는 반려 처리를 할 수 있다. |
| 🟡 P1 | **운영자**는 미션 진행 현황을 한눈에 파악하기 위해 통합 대시보드에서 전체 미션의 상태와 주요 수치를 확인할 수 있다. |
| 🟢 P2 | **운영자**는 반복 미션 운영 효율을 높이기 위해 기존 미션을 복제하여 새 미션을 생성할 수 있다. |

---

### 3-3. 미션 탐색 & 지원 (참여자 주도)

| 우선순위 | 유저 스토리 |
|---------|------------|
| 🔴 P0 | **참여자**는 원하는 미션을 찾기 위해 카테고리, 지역, 보상금액 조건으로 미션 게시판을 필터링할 수 있다. |
| 🔴 P0 | **참여자**는 미션 내용을 확인하기 위해 미션 상세 페이지(수행 조건, 보상, 마감일)를 열람할 수 있다. |
| 🔴 P0 | **참여자**는 미션에 참여하기 위해 지원하기 버튼을 눌러 지원 신청을 할 수 있다. |
| 🟡 P1 | **참여자**는 자신의 활동 현황을 파악하기 위해 '내 미션' 대시보드에서 진행중/완료/반려 상태를 확인할 수 있다. |
| 🟢 P2 | **참여자**는 관련성 높은 미션을 빠르게 발견하기 위해 자신의 설정 지역 기반 추천 미션을 받을 수 있다. |

## 4. 기술 아키텍처 결정사항

### 프론트엔드 스택

```yaml
Framework: Next.js 14 (App Router)
Language: TypeScript (strict mode)
Styling: Tailwind CSS + shadcn/ui (컴포넌트 라이브러리)
State Management: Zustand (클라이언트 전역 상태)
Server State: TanStack Query (API 캐싱 & 동기화)
Form: React Hook Form + Zod (유효성 검사)
이미지 업로드: react-dropzone
```

**결정 근거:**
- Next.js App Router의 Server Component로 초기 로딩 성능 최적화
- TypeScript strict mode로 역할별 권한 타입 안전성 보장
- Tailwind + shadcn/ui로 디자인 일관성과 개발 속도를 동시에 확보

---

### 백엔드 스택

```yaml
Runtime: Node.js 20 LTS
Framework: Express.js (REST API)
Language: TypeScript
인증: JWT (Access Token 1h + Refresh Token 7d)
권한 관리: RBAC Middleware (operator / participant / client)
파일 업로드: Multer (MVP: 로컬 스토리지 → v1.1: AWS S3 전환)
유효성 검사: Zod
API 문서화: Swagger (OpenAPI 3.0)
```

**결정 근거:**
- Refresh Token 도입으로 보안성과 사용자 편의성 균형 확보
- Zod를 프론트/백 공유 스키마로 활용하여 타입 일관성 유지
- Multer 로컬 → S3 전환을 환경변수 스위칭으로 처리하여 마이그레이션 비용 최소화

---

### 데이터베이스

```yaml
Primary DB: PostgreSQL 15
ORM: Prisma (타입 안전 쿼리)
마이그레이션: Prisma Migrate
캐싱: Redis (세션, 중복 지원 방지 잠금) — P1 단계 도입
```

**핵심 도메인 엔티티:**

```
User (id, email, role, createdAt)
  ├── ParticipantProfile (userId, region, snsChannels, totalPoints)
  └── ClientProfile (userId, businessName, contactInfo)

Mission (id, title, category, region, reward, quota, status, clientId)
  ├── MissionApplication (id, missionId, userId, status)
  └── ContentSubmission (id, applicationId, type, fileUrl, snsUrl, text, status, reviewNote)

PointTransaction (id, userId, amount, type, referenceId)
WithdrawalRequest (id, userId, amount, bankInfo, status)

Report (id, missionId, participantCount, contentCount, reachEstimate)
```

---

### 인프라/클라우드

```yaml
컨테이너화: Docker + Docker Compose
CI/CD: GitHub Actions
MVP 배포: 단일 서버 (VPS or AWS EC2)
파일 스토리지: 로컬 볼륨 (MVP) → AWS S3 (v1.1)
역방향 프록시: Nginx
SSL: Let's Encrypt (Certbot)
환경 관리: .env 파일 + Docker secrets
```

### 컴포넌트 간 핵심 흐름

```
[고객사 의뢰 등록]
고객사 Portal → POST /api/missions/request → Mission Module → DB 저장
→ 운영자 대시보드 알림

[미션 지원 및 매칭]
참여자 App → POST /api/applications → Application Module → 운영자 승인 대기
→ PATCH /api/applications/:id/approve → 참여자 상태 업데이트

[콘텐츠 검수 → 정산]
참여자 → POST /api/submissions (multipart/form-data)
→ Content Module → 파일 저장 → DB 기록
→ 운영자 PATCH /api/submissions/:id/approve
→ Settlement Module → PointTransaction 생성 → 참여자 잔액 증가
→ 참여자 출금 신청 → 운영자 지급 처리 완료
```

## 6. 비기능 요구사항

### 성능 (Performance)

| 항목 | 목표 기준 |
|------|----------|
| API 응답 시간 | 일반 CRUD: p95 < 300ms |
| 이미지 업로드 | 파일당 최대 10MB, 업로드 완료 < 5초 |
| 미션 목록 페이지 로딩 | FCP < 1.5초 (Next.js SSR 활용) |
| 동시 접속 지원 | MVP 기준 최소 200 concurrent users |

### 보안 (Security)

```
✅ JWT Access Token 만료: 1시간
✅ Refresh Token 만료: 7일 (HttpOnly Cookie 저장)
✅ RBAC: 모든 API 엔드포인트에 역할 미들웨어 적용
✅ 파일 업로드: MIME 타입 화이트리스트 (image/jpeg, image/png, image/webp, video/mp4)
✅ 파일 크기 제한: 이미지 10MB, 영상 100MB
✅ SQL Injection 방지: Prisma ORM 파라미터 바인딩
✅ XSS 방지: DOMPurify 적용 (사용자 입력 텍스트)
✅ Rate Limiting: 로그인
